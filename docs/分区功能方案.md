# 音言 · 音乐分区功能方案

> 参考对象：网易云音乐 App 三张截图（音乐专区网格页 / 搜索页 / 搜索落地页），2026-09-12。
> 原则延续项目既有约定：**数据驱动、不硬编码** —— 分区完全由 `Categories` 表驱动，加分区 = 插一行数据，零代码改动。

---

## 一、网易云三张截图的取舍分析

| # | 网易云设计点 | 取舍 | 理由与落地方式 |
|---|---|---|---|
| 1 | 「音乐专区」双列彩色卡片网格（名称 + 图标 + 一句 slogan，每卡独立底色） | ✅ 核心采纳 | 与 Categories 表完美对应：名称=Name，slogan/颜色/图标=新增 3 个展示字段。整页就是"全部专区"页 |
| 2 | 「快速发现」横滑大卡（发现页顶部） | ✅ 采纳（简化版） | 发现页加"音乐专区"横滑区，纯色卡起步；横滑放不下时点"更多"进全部专区页 |
| 3 | 分区详情：顶部主题色头部 + 该分区内容列表 | ✅ 采纳 | 分区页头部用分区色 + 名称 + slogan，下方列出该分区歌单（接口现成） |
| 4 | 搜索页顶部「专区」快捷图标入口 | ⏳ 二期 | 有价值但优先级低；入口先放发现页 |
| 5 | 热搜榜 / 热歌榜双卡 | ⏳ 二期 | 我们有 `Songs.PlayCount` 且歌曲搜索默认按播放量排序，做"热歌榜"卡成本很低 |
| 6 | 猜你喜欢 / 智能搜索 | ❌ 暂不 | 需要推荐数据与算法，超出当前范围 |
| 7 | 顶部大图 banner + 浏览全部编辑卡 | ❌ 暂不 | 需要运营素材（封面图/文案），等分区稳定后三期再考虑给 Categories 加 CoverUrl |
| 8 | 识曲 / 听书 / 曲风等额外入口 | ❌ 不做 | 与本项目范围无关 |

**核心结论：采纳的三个点本质是同一个数据结构（分区卡片）的三种展示位置** —— 发现页横滑区（入口）、全部专区页（网格）、分区页（详情）。一套数据三处复用。

## 二、总体设计

```
发现页(HomeView)                    全部专区页(ZonesPage)              分区页(ZonePage)
┌─────────────────┐     "更多>"    ┌──────────────┐   点卡片          ┌──────────────────┐
│ 音乐专区    更多 >│ ───────────→ │ ┌────┐ ┌────┐ │ ──────────────→ │ ██ 主题色头部     │
│ [华语][粤语][K-pop]│              │ │华语│ │粤语│ │                 │ ██ 名称+slogan   │
│  (横滑彩色卡)     │              │ └────┘ └────┘ │                 │──────────────────│
│ 热门歌曲 ...      │              │ │K-pop│ │欧美│ │                 │ 该分区下的歌单列表 │
└─────────────────┘              │ └────┘ └────┘ │                 │ (复用歌单卡片UI)  │
                                 └──────────────┘                 └──────────────────┘
```

- **数据模型**：`Categories` 新增 3 个可空展示字段 `Slogan`（宣传语）、`ColorHex`（卡片底色）、`IconGlyph`（MaterialIcons 码点）。名称唯一索引已有。
- **内容组织**：MVP 分区只挂**歌单**（`Playlists.CategoryId`，可空外键已有）。歌曲打标是语言维度，自动打标准确率低（`Artist.Region` 271 位歌手全空），后置。
- **接口**：零新增 —— 歌单按分区过滤 `api/playlists?categoryId=x`、歌曲按分区过滤 `api/songs?categoryId=x` 均已存在；分区列表 `GET api/catalog/categories` 已存在。
- **分区数据来源**：运营性质数据，直接 SQL 插入（`POST categories` 需 admin 角色，当前无人持有）。

## 三、MVP 范围（本次实现）

### 3.1 数据库（`Program.cs` 幂等 raw SQL，沿用项目惯例）

```sql
ALTER TABLE "Categories" ADD COLUMN IF NOT EXISTS "Slogan"    text NULL;
ALTER TABLE "Categories" ADD COLUMN IF NOT EXISTS "ColorHex"  text NULL;
ALTER TABLE "Categories" ADD COLUMN IF NOT EXISTS "IconGlyph" text NULL;

INSERT INTO "Categories" ("Name", "Slogan", "ColorHex", "IconGlyph")
VALUES
  ('华语专区',  '华语流行 · 音乐坐标',      '#E53935', '&#xE405;')  -- music_note
  ('粤语专区',  '探索大湾区优质好音乐',    '#EC407A', '&#xE03D;')  -- queue_music
  ('K-Pop专区', '热歌唤醒你的 DNA',        '#8E24AA', '&#xE87D;')  -- favorite
  ('欧美专区',  '环球热单一站收听',        '#1E88E5', '&#xE80B;')  -- public
  ('日语专区',  '捕捉最新日系风潮',        '#00897B', '&#xE8E2;')  -- translate
ON CONFLICT ("Name") DO NOTHING;
```

> 颜色/图标/slogan 都是数据，之后随时 `UPDATE` 调整，不碰代码。图标码点显示效果需真机核对，微调只改数据。

### 3.2 后端（3 处小改）

1. `Category` 实体：加 `Slogan? / ColorHex? / IconGlyph?`（长度 100/16/16，均空即可用）。
2. `CategoryDto`：末尾加**带默认值可选参数**（`string? Slogan = null, string? ColorHex = null, string? IconGlyph = null`，沿用 PlaylistDto 的做法，不动既有构造点）。
3. `CatalogService.GetCategoriesAsync` 投影补 3 个字段。

歌单/歌曲按 categoryId 过滤的接口**不改一行**。

### 3.3 客户端（2 个新页面 + 发现页一节 + 路由）

| 改动 | 内容 |
|---|---|
| `HomeViewModel` / `HomeView` | 加回 `GetCategoriesAsync` 拉取（上轮删的那次请求回来了，这次有 UI 消费它）；发现页 logo 下方新增「音乐专区」节：横滑 `ScrollView` 彩色卡（底色=ColorHex、图标+名称+slogan 单行），节标题带「更多 >」 |
| 新页面 `ZonesPage`（全部专区） | 双列网格，同款卡片铺满，样式对齐截图 1 |
| 新页面 `ZonePage`（分区详情） | 顶部主题色头部（名称+slogan+图标，底色=ColorHex）+ 该分区歌单 `CollectionView`（复用现有歌单卡片模板），空态文案「该专区还没有公开歌单」 |
| `MauiProgram.cs` | `Routing.RegisterRoute("zone", ...)`、`Routing.RegisterRoute("zones", ...)`（与现有 playlist/artist 路由同款） |
| 导航参数 | `zone?categoryId=&name=&slogan=&colorHex=&icon=` 查询串传递，避免分区页二次请求 |

### 3.4 歌单内容从哪来（MVP 的空页问题）

分区页没内容会很难看，MVP 用两层解决：
1. **SQL 打标现有歌单**：把库里已有的 3 个歌单中合适的手动 `UPDATE "Playlists" SET "CategoryId" = ...`（量小，人工判断即可）。
2. **建歌单选分区（二期做 UI）**：`CreatePlaylistRequest.CategoryId` 字段后端早就有，只差建歌单弹窗加一个分区选择器；MVP 先不做，用户建完歌单后临时用 SQL 归类。

### 3.5 验收标准

- [ ] 发现页「音乐专区」横滑卡正常渲染颜色/图标/slogan，点卡片进分区页
- [ ] 全部专区页双列网格完整展示 5 个分区
- [ ] 分区页头部主题色正确，列表只显示该分区歌单，空分区显示占位文案
- [ ] 新增一个分区（纯 SQL）后，App 重启即出现在横滑区与网格里，无需改代码
- [ ] 老库升级幂等：重复启动 Api 不产生重复种子数据（ON CONFLICT 兜底）

## 五、三期 / 明确不做

- Categories 加 `CoverUrl`，横滑卡升级为封面图大卡（对齐截图 3「快速发现」）——需要运营素材。
- 歌曲打标工作流（Scanner 按关键词辅助 + 人工复核）。
- 猜你喜欢、智能搜索、识曲、听书：不做。

## 六、风险与备注

- **图标码点显示效果**需真机核对（MaterialIcons 字体覆盖度），微调只改数据。
- **单维度限制**：一首歌/一个歌单只能挂一个分区；若日后要"语言 + 曲风"双维度，需改多对多标签表——当前明确不做。
- 纯白主题下卡片是分区自有底色（数据指定），不受主题换肤影响；卡上文字用白色，对比度由种子色保证（都取 400~600 深度色）。
- 全部改动走幂等 SQL + 可选参数 DTO，对老库/新库均安全；Api 需重启一次让补列生效。
